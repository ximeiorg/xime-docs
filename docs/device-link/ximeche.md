# 桌面端（曦码·澈）

Linux 上不需要额外安装 ximed：直连节点就跑在**曦码·澈输入法的 daemon（`xime-daemon`）**里，配对入口在设置程序的「设备关联」页。

> 节点随输入法服务常驻：登录 Plasma 后由 KWin 拉起快启动器再启动 daemon，之后一直存活。只要输入法服务在运行，配对过的设备就保持发现与重连，不需要单独开一个托盘应用。

> 曦码·澈只支持 **KDE Plasma 的 Wayland 会话**。X11 会话、GNOME 等其它合成器下输入法本身无法启用，设备互联自然也用不了。

## 前提

- 已按[总览与安装](/ximeche/install)完成安装，KWin 的虚拟键盘指向 `xime-launcher.desktop`，并已重新登录。
- daemon 在运行：`pgrep -a xime-daemon` 能查到进程。
- 两台设备连同一个 Wi-Fi、同一网段，路由器没有开 AP 隔离或访客网络隔离。

## 打开设置程序

三种方式任选：

- 候选窗右侧菜单 →「设置」
- 托盘右键 →「设置...」
- 直接运行 `xime-setup`

## 页面说明

「设备关联」页分三块：

| 区域 | 内容 |
|------|------|
| 本机 | 设备名（可编辑，点「保存」生效）与设备标识（由本机密钥派生，只读） |
| 配对 | 标签栏切换「显示配对码 / 输入配对码」，一次只显示一个方向 |
| 已配对设备 | 设备名与标识前几位，附「最近地址」或「尚未连接过」；右侧「移除」（需二次确认） |

设备名只用来让对方认出这台机器，建议写清是哪台，例如「书房台式机」。设备标识用于两端对照确认是同一台机器，排障时用得上。

## 配对

两台设备连同一个 Wi-Fi，任选一个方向。配对码只经人眼传递，不会出现在网络报文里。

### 本机显示配对码

1. 「设备关联 → 显示配对码」→ 点「生成配对码」。
2. 页面显示 6 位数字与倒计时，**60 秒内有效**。
3. 在另一台设备（手机或另一台电脑）上输入这组码完成配对。
4. 过期后显示「已过期，请重新生成」；点「换一个」换一组，点「取消」立刻作废。

### 输入对方显示的配对码

1. 切到「输入配对码」，填入对方显示的 6 位数字（输入框提示为 `例如 482 719`）。
2. 点「配对」，按钮变为「正在查找设备…」，自动在同一 Wi-Fi 下发现对方，**最长等 60 秒**。
3. 成功后页面顶部显示状态条，设备出现在「已配对设备」里。

如果局域网广播被拦（AP 隔离、公司网络），展开 **手动地址** 填对方的 `192.168.1.5` 或 `192.168.1.5:47823` 再配对。

配对只建立信任关系，**不会自动开启同步**。

## 开启同步

到 **设置 → 剪贴板 → 剪贴板同步**。这里是开关式多选，不是下拉单选：

| 开关 | 说明 |
|------|------|
| 局域网直连 | 与配对过的设备点对点传输，不经第三方服务器；副标题显示「已配对 N 台，不经过任何服务器」 |
| 同步插件 | 安装剪贴板同步插件后经 WebDAV 等通道跨网络同步；开关名称随已选插件变化 |

- **勾选即生效**：开关一变就写入 `clipboard_sync.toml`，daemon 在 200 毫秒内感知并重选通道，**不需要重启输入法**。
- 两个都勾时**直连优先**：直连可用时只走直连，插件通道不拉取、不推送，避免同一内容被推两次。
- 直连**掉线后立即**让位给插件（连接状态由节点事件直接告知，不用等满一个超时）；插件通道每 **2 秒**拉取一次。直连恢复并连上后立刻切回。
- 只勾直连就只走直连，不会偷偷改走插件；两个都不勾时页面显示「同步已关闭」，剪贴板只留在本机。
- 还没有配对设备时，直连开关的副标题会提示「还没有已配对设备，先到『设备关联』配对」，旁边还有「去配对」按钮直达配对页。

## 什么时候会同步

- 同步桥是 daemon 里的**独立线程**，推送 / 拉取不会阻塞打字；输入法停用（`Ctrl+Space`）时 daemon 仍在运行，同步不受影响。
- 关闭设置程序窗口不影响同步——它只是配置前端，节点在 daemon 里。
- 复制后几秒内送到对端；对端收到后**直接写入系统剪贴板**，可以立刻 `Ctrl+V`，同时也会进入 `xime.db`，在候选窗「剪切板」面板里能看到这条记录。
- 连接建立后会自动**补推**一次本地最近一条剪贴板，避免「刚复制完才连上，对方收不到」。
- 同步只处理「当前这一条」，不会把剪贴板历史整体上传；历史仍留在各自设备本地。
- 只同步**文本**。图片、文件不会通过这条通道传输。

## 管理已配对设备

- **移除**：在「已配对设备」里点「移除」，会先要一次确认（「确认移除？」），确认后删除信任关系；对方需要重新配对。
- **改名**：改「本机 → 设备名」并点「保存」，下次配对或同步时告知对端；已配对设备上显示的旧名不追溯更新。
- **多台设备**：可以配对多台，但剪贴板是单值资源，同一时刻只保持一条直连。设备较多时建议只保留常用的几台。

## 数据与日志

| 路径 | 内容 |
|------|------|
| `~/.config/xime/p2p/identity.bin` | 本机身份密钥（`0600`），与设置程序共用同一份 |
| `~/.config/xime/p2p/peers.json` | 已配对设备表 |
| `~/.config/xime/clipboard_sync.toml` | 同步通道配置（`enabled` + `channels`，首个优先） |
| `~/.config/xime/xime.db` | 剪贴板历史与快捷发送（统一库） |
| `~/.config/xime/xime.log.YYYY-MM-DD` | 运行日志，搜 `Sync p2p` / `Sync bridge` / `Sync:` 可看到节点端口、连接与通道切换 |

删除 `p2p/` 目录等于重置身份：所有旧配对都会失效，需要重新配对。删除前先退出输入法（退出后 daemon 重启会重新生成身份）。

端口固定为 TCP `47821`（直连）、UDP `47822`（局域网发现）、`47823`（配对）；被占用时会自动向后顺延，因此防火墙建议**按程序放行 `xime-daemon`**，不要只放行固定端口。

## 排查

| 现象 | 可能原因与处理 |
|------|----------------|
| 配对成功但剪贴板不同步 | 「剪贴板 → 剪贴板同步」里的「局域网直连」开关没勾，配对不等于同步 |
| 生成配对码后对方找不到 | 同一 Wi-Fi、同一网段；关闭 VPN；路由器未开 AP 隔离；必要时用手动地址 |
| 输入配对码一直「正在查找设备…」 | 对方页面是否还开着、码是否过期（60 秒）；防火墙是否拦了 daemon |
| 改了开关但行为没变 | 正常情况 200 毫秒内生效；仍无变化时看日志有没有 `Sync bridge: config changed`，没有就说明配置文件路径不一致（`~/.config/xime/clipboard_sync.toml`） |
| 设置程序关掉后同步停了 | 不会。节点在 daemon 里；真正会断的是 daemon 退出（`pgrep -a xime-daemon` 为空） |
| 收到内容但 `Ctrl+V` 是旧的 | 系统剪贴板写入失败（日志有 `system clipboard unavailable`），内容只在历史里；确认当前是 Wayland 会话 |
| 日志里反复出现端口占用 | 上一次 daemon 异常残留，`pkill xime-daemon` 后重新登录或触发一次虚拟键盘 |
| 移除设备后对方还能看到本机 | 需要在两端都移除；只在一端删，另一端仍保留旧配对记录 |

更多问题见[设备互联常见问题](/device-link/faq)，输入法本身的问题见[曦码·澈常见问题](/ximeche/faq)。
